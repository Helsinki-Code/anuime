# AnUIme enhancement review

Reviewed 5 October 2026 against `anuime.md` and the current repository.

## Assessment

AnUIme has the foundation of a useful character-driven registry. Its next milestone should be reliable installation, faithful rendering, useful compositions, and documented release evidence. Adding more catalog entries before closing these gaps would increase maintenance faster than product value.

The proposal describes twelve deeply finished launch components. The repository has expanded much further: 63 component metadata files, 70 block metadata files, 42 advanced UI metadata files, three themes, one recipe library, and one base item. These are filesystem inventory counts, not proof that every entry builds, installs, or is equally finished. Together they represent 180 registry metadata entries; 105 are declared `registry:ui` across components and advanced items. Studio maintains 52 selectable IDs, including the authentication block. README and execution-plan counts of 51 components and ten blocks are stale.

The review covered the repository inventory and a static scan of 823 text files across source, registry, packages, apps, scripts, fixtures, browser tests, design specifications, and CI. Detailed inspection focused on the public workflow, shared recipe contract, representative components and blocks, authentication, persistence, AI service, MCP, and quality gates. This is not a claim of manual line-by-line review of every file or runtime verification of every component.

Build/test execution was unavailable: this checkout has no installed `node_modules/.bin/vp` or Vitest, and `vp` and Bun were not on PATH. No dependencies were installed, no deployed application was audited, and no external alpha-user results were verified. Findings below distinguish source-confirmed gaps from validation work that still needs execution.

## What already exists

- Three documented character systems, original-art provenance records, extracted design laws, and a recorded semantic contrast audit.
- Versioned deterministic recipes, URL sharing, local recipe history, undo/redo, responsive preview controls, and manual Studio editing.
- File-backed registry metadata/source, JSON distribution, authored MDX, search, Markdown endpoints, LLM discovery files, SEO utilities, and prerender configuration.
- Unit tests, Playwright tests, automated accessibility checks, visual snapshots, and three consumer fixtures.
- A curated six-example gallery and a separate SQLite-backed submission API.
- A feature-gated AI Director with structured proposals, CSRF protection, service timeout, disabled shell/file/web/subagent tools, and a network-denied sandbox.
- Local and HTTP MCP interfaces for discovery, source retrieval, composition, personas, and deterministic design review.
- Root-route security headers, production-only secure session cookies, and anonymous event plumbing that respects Do Not Track.

These should be strengthened rather than rebuilt.

## Recommended sequence

1. **Release baseline:** restore the documented Vite+/Bun environment; run check, doctor, unit tests, build, browser tests, and fixture builds. Record failures and catalog inventory. Complete E01–E08 for any features being exposed.
2. **Ship fidelity:** implement E09–E15, fix dialog/date/tooltip/ID issues, and prove Button, Input, Card, Dialog, Select, Tabs, and Data Table in fresh consumers. Make exported snippets usable.
3. **Make Studio truthful:** implement compatibility and dimension semantics, fix shortcuts/storage/URL normalization, repair image export, and align Studio with reviewed catalog capabilities.
4. **Make blocks useful:** review the 70 blocks by actual job, replace generic specimen grids, add data/callback APIs, and support full-composition remix/export. Demote unfinished items to experimental.
5. **Close release evidence:** extend browser/accessibility/visual coverage, execute AI evals if enabled, add operational budgets, reconcile documentation, and run external walkthroughs.
6. **Choose the next business feature from usage:** cloud saves, AI beta, or community publishing. Add billing and teams after demonstrated demand.

## Definition of a credible next release

- Protected production features fail closed without explicit configuration.
- Published data survives deploys and account deletion/remix behavior is tested.
- Every advertised stable item installs with declared dependencies in supported consumers.
- Installed screenshots and interactions match the preview, including fonts, themes, and reduced motion.
- Studio controls have defined, tested effects; exported snippets compile.
- Core interactions have no unresolved critical accessibility or security findings.
- Catalog counts, status, docs, discovery APIs, and release claims agree.
- Real external users can complete the primary workflow without assistance.

The strongest immediate enhancement is completing the promise already made: choose a character, shape the system, and ship source that behaves and looks like the preview.
